    Tooling¶

    The compiler, stenopos, is also the formatter, linter, doc generator, test runner and language server, so there are no extra tools to install. This page covers using them on single files. In a project, tagma fmt, tagma lint, tagma doc and tagma test run the same tools over all of its sources (see Projects with tagma).

    stenopos fmt¶

    Format source to the canonical style: 4-space indentation by brace depth, trimmed trailing whitespace, collapsed blank runs, and a single trailing newline. Comments and string contents are preserved exactly.

    stenopos fmt src/main.sten          # reformat in place
stenopos fmt --check src/*.sten     # report unformatted files, exit 1 (for CI)

    Formatting is idempotent — running it on already-formatted code changes nothing.

    stenopos lint¶

    Report style and correctness lints over the parsed source.

    stenopos lint src/*.sten

    The current checks cover naming conventions (snake_case for functions and parameters, PascalCase for types and enum variants) and flag empty function bodies. Exit code is 1 if any lints are found.

    stenopos doc¶

    Generate a Markdown API reference for a module's public surface — its pub functions, structs, enums, traits, and type aliases, with full signatures and the prose from their /// doc comments.

    stenopos doc src/vector.sten              # print to stdout
stenopos doc src/vector.sten -o vector.md # write a file

    /// Computes the area of a circle given its radius.
pub func circle_area(float64 radius) -> float64 {
    return 3.14159 * radius * radius
}

    renders the signature followed by "Computes the area of a circle given its radius."

    stenopos test¶

    Discover the @test functions in a file, run them, and report pass/fail.

    // math_test.sten
func add(int32 a, int32 b) -> int32 { return a + b }

@test
func test_add() -> void {
    if (add(2, 3) != 5) {
        fail("add(2, 3) should be 5")
    }
}

    stenopos test math_test.sten
# running 1 test(s) from math_test.sten
# test test_add ...
# ok — 1 test(s) passed

    A test signals failure by aborting (for example via fail); the runner reports a non-zero exit when any test fails.

    Seeing the generated code¶

    stenopos emit-ir src/main.sten main.ll   # the LLVM IR the compiler produces

    stenopos explain¶

    Every diagnostic is tagged with an error code — error[E0300]: .... Pass that code to stenopos explain for a long-form explanation of the whole class of problem, with guidance on how to fix it:

    stenopos explain E0300

    E0300 [type error]

The expected type does not match the actual type. Stenopos does not
perform implicit type conversions. Use `cast[T]()` for safe numeric
conversions or `.to_X()` methods for other conversions.

    Codes are grouped by compiler phase: E01xx lexer, E02xx parser, E03xx type, E04xx memory/ownership, E05xx security. explain knows every standard code, so you can look one up straight from the error[...] tag in a build's output.

    stenopos lsp¶

    The language server. Your editor starts it and talks to it over standard input and output using the Language Server Protocol.

    • Diagnostics come from the real type checker, run on the unsaved buffer, so they match a build exactly.
    • Hover, go to definition and completion use the compiler's own lexer, so they keep working while the file is mid-edit. They cover functions, methods, structs, classes, enums and traits, including the public names of modules the file imports.

    Neovim¶

    vim.filetype.add({ extension = { sten = "stenopos" } })
vim.api.nvim_create_autocmd("FileType", {
  pattern = "stenopos",
  callback = function(args)
    vim.lsp.start({
      name = "stenopos-lsp",
      cmd = { "stenopos", "lsp" },
      root_dir = vim.fs.dirname(args.file),
    })
  end,
})

    VS Code¶

    A small extension that starts stenopos lsp as its server:

    import { ExtensionContext } from "vscode";
import { LanguageClient, TransportKind } from "vscode-languageclient/node";

export function activate(_ctx: ExtensionContext) {
  const serverOptions = { command: "stenopos", args: ["lsp"], transport: TransportKind.stdio };
  const clientOptions = { documentSelector: [{ scheme: "file", language: "stenopos" }] };
  new LanguageClient("stenopos", "Stenopos", serverOptions, clientOptions).start();
}

    Register the stenopos language for .sten files in the extension's package.json (contributes.languages).
