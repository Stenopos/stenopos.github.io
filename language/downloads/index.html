    What's new in v1.0.0-rc.6

    Added¶

    • A line that starts with an operator no statement can start with (+, /, %, a comparison, &&, ||, ^, <<, >>, ??, ., ?.) continues the line above, so long expressions and method chains break before the operator. -, * and & can start a statement, so they still break after it. A blank or comment-only line ends the statement; an operator starting the line after one is an error that says so (it used to surface later as an unrelated "undefined variable"). Example leading_operator_lines; found porting Tux.
    • Every release publishes its benchmark numbers: the tagged commit's bench run (each workload against C: binary size, run and build instructions, peak memory) is attached as a signed benchmarks.tsv, and tests/bench/report.sh turns it into the release notes' Performance section (benchmarks.md), with what moved since the previous release beyond the gate's tolerances and every program over its budget. The docs site embeds the same report in the release post and keeps every release's numbers on its Performance page.
    • tagma retract <version>: sign a retraction and commit it to a registry checkout (the package's CI runs it on a signed retract/<version> tag). A retracted version is never chosen anew, but existing locks keep building.
    • Revoking a publisher key (ADR-0039 amended; registry FORMAT.md): a key statement may carry revoked = "<date>". Versions the key signed on or after that date are revoked (never used, even when locked; a build with one locked fails once its copy of the index updates), its later retractions are void, it can sign nothing new (publish and retract refuse it), and the revocation can't be undone. registry check --previous accepts a new entry or retraction only when it is dated today or yesterday (UTC), so a stolen key can't backdate one. 67 package checks in the bootstrap (was 48).
    • str_from_byte(int32 b) -> str: a one-byte string from a byte value (0-255; any other value stops the program like an index out of bounds). It is pure (no capability or effect). With it std now holds any byte and any character: std.string.from_code_point encodes a Unicode character as UTF-8, std.bytes.to_str turns any bytes into a string, and std.toml reads every TOML escape (\b, \f, \u, \U) (std 6efc157, L63). Example str_from_byte.
    • STENOPOS_TEST_WRAP runs stenopos test/tagma test binaries under a checker (valgrind --leak-check=full --error-exitcode=99); its failure fails the run. The examples and course repositories' CI now run every program and test suite under valgrind this way.
    • Examples discard_frees, temp_list_args, nested_container_signatures, list_ownership (each valgrind-gated).
    • scripts/tomlfuzz.py, run in CI's fuzz step with a fresh seed per build: std.toml against Python's tomllib on generated and mutated documents. It must read every valid document the same way, never accept invalid TOML, and reject only what it documents as unsupported. Its first run found std.toml reading 007 as 7 (std 6e23cf1 rejects leading zeros; std.lock bumped).
    • scripts/valgrind-toolchain.sh, run in CI next to valgrind-examples.sh: the compiler itself under valgrind checking every example, and tagma's registry checker (TOML, SHA-256/512, Ed25519, SSH signatures), resolver, a Tagma.toml edit and a project check. Both are now valgrind-clean.
    • The package commands (M4 step 6, ADR-0039 §4.7, §4.8). tagma add <ns/name>[@<version>] depends on a registry package at its newest version (or the one given) and grants it what it and its dependencies use (or what --allow says); remove drops a dependency; update [<name>] raises requirements to the newest version of their major version and reports new major versions. Each edits one line of Tagma.toml, keeps the rest as written, then re-resolves, fetches and checks everything, and puts Tagma.toml, Tagma.lock and vendor/ back on any problem (a version that needs more than its grant is refused, naming the capability). tagma vendor copies the locked packages into vendor/, which builds then use alone, checking each package's content hash. tagma caps prints the capabilities a package's own code uses, found by tagma check --allow <caps>, which holds every file of the package to a set of capabilities. tagma publish publishes the current commit: its files are hashed, tested and checked for capabilities, and the entry is written into a registry checkout, signed with a publisher key, checked and committed. tagma registry verify --previous <dir> re-derives every new entry from its source (hash, manifest, dependencies, capabilities), for the registry's CI. --registry <checkout> uses a local checkout of the index for any command. 48 checks in the bootstrap.
    • Function types and lambda parameters take any type: fn(List[int32])->int32, fn(HashMap[str, int32], str)->int32?, |List[int32] ys| -> void { .. }.
    • scripts/build-tagma.sh builds tagma from a seed at this commit, for the registry's pipeline (as build-compiler.sh does the compiler for the examples and the course).
    • Strings order with <, <=, >, >=, byte by byte (runtime stenopos_string_cmp). tagma's own comparison helper is gone.
    • A named function is a value of its function type: fn(int32)->int32 f = square, or apply(square, 5). The compiler emits an adapter per function so it fits the closure calling convention. Taking a function as a value needs its capabilities and effect bound, as a call does; generic and extern functions are refused with a pointer to wrapping them in a lambda.
    • Capability grants (M4 step 4, ADR-0039 §4.6). A registry dependency may use only what every grant on every path to it allows: the project's allow in Tagma.toml, then each package's grants to its own dependencies. tagma refuses a build whose locked capabilities exceed that, naming the package and the capability, and the compiler holds each package's code to the same limit: a function may declare only granted capabilities, unsafe needs Memory, and extern "C" and asm need System. The driver marks which file each part of a program came from, so a package can't forge a marker to escape its limit. 9 checks in the bootstrap.
    • Fetching registry packages (M4 step 3). tagma fetch, and every build, run, check and test of a project with registry dependencies, keep a clone of the index in the cache and use it only after tagma registry check passes on it with its snapshot (signed, unexpired, not older than one already seen; a refused copy is rolled back). Packages are fetched by commit (GitHub, then the mirror) and used only while their files match the content hash in Tagma.lock, checked on every build. A lock that satisfies Tagma.toml builds without the index; --offline and --locked work. Tagma.lock records each package's repository. STENOPOS_CACHE, STENOPOS_REGISTRY_URL and STENOPOS_REGISTRY_ROOT select another cache or registry. 12 end-to-end checks in the bootstrap, against a registry signed at test time and served from local git repositories.
    • The registry checker limits repository URLs to https:// and letters, digits and - . _ / (they are passed to git).
    • Minimal version selection over the registry index (ADR-0039 §4.5) and Tagma.lock (tagma fetch; tagma resolve, the resolver alone, is kept for its tests and left out of the help). A requirement selects the lowest matching version, requirements are followed through every selected version and through path dependencies' manifests, and each package and major version gets the highest version reached; retracted versions are skipped unless the lock names one. Tagma.lock records each version's commit, content hash, capabilities and exact dependencies; --locked refuses a change. Tested in the bootstrap (diamonds, superseded requirements, two majors, retractions, missing versions, path dependencies, --locked). (M4 step 2.)
    • tagma registry: check validates a checkout of the package registry against its format (Stenopos/registry FORMAT.md, version 1): names, versions, entries, key statements, every signature (entries, retractions, key statements, the snapshot), the snapshot's coverage and expiry, and with --previous that a change only adds versions and retractions. statement, retract-statement, snapshot and hash produce what publishers and CI sign. Tested on a signed fixture and 19 ways of tampering with it, in the bootstrap. (M4 step 1, ADR-0039.)
    • Null narrowing follows && and ||: the right side of x != null && ... and of x == null || ... sees x as non-null, and an if whose condition is such a chain narrows its branches (and the rest of the scope after a guard that returns) for every variable in the chain.
    • Struct parameters are borrowed (ADR-0040 §4.3). A function that sets a field of a struct parameter changes the caller's struct, as a method changing this already did; direct calls used to deep-copy each struct argument, so the change was lost. Reassigning a parameter rebinds it without touching the caller's value (it used to fail in llc), and spawn still gives the new Hemerodrome its own copy.
    • The exclusivity rule (ADR-0040 §4.3): the compiler infers which parameters each function changes, through the calls it makes and to a fixpoint for recursion, and rejects a call that passes a place to such a parameter and also passes it, or a value inside it, in another argument: f(a, a), f(a, a.items), a.merge(a). The error names the parameter and gives the copy to make.
    • The import forms: import a.b.name (one name, no braces), import a.b.* (every public name), paths relative to the importing module (import self.utils.{f}, import super.shared.*), and pub import, which re-exports names so a facade module can present items defined elsewhere (re-exports chain; aliases follow them too). super above a top-level module and pub import of a whole module are errors. A name imported explicitly beats the same name offered by *; two * imports offering different items under one name make a use of it an "ambiguous" error, and so do two explicit imports of it from different modules (the same item reached through a re-export is not a clash). The same holds for functions, structs, enums and type aliases.
    • protected class members: a protected field or method is open to its class's module and to the methods of the class and its subclasses, in any module; other code gets an error naming who may use it. protected on a struct member or a top-level item is an error. An inherited field is judged by the class that declares it, and an inherited method's body resolves names in its defining module. A struct literal of a class declared in the current module may set every field, inherited ones too.
    • Fields and methods without this.: inside a method, balance += x and fee() mean this.balance and this.fee(). A local or parameter of the same name wins over a field, and a method over a free function.
    • as and qualified names: import geo.flat.describe as describe_flat and import geo.{Point as GeoPoint} import an item under another name (the original name is then not imported); pub import self.flat.{make as flat_point} re-exports under another name. A module imported whole (import geo.flat, or import geo.round as r) qualifies names: flat.make(1, 2), flat.Point p, r.Point { r: 5 }, flat.Side.Right, flat.ORIGIN_X, flat.Meters. Inside the importing module the qualifier names only the module, so a variable can't take it, and two modules can't share one. A qualified name that misses says why: private, or not in that module.
    • Top-level consts belong to their module: a const is visible in its own module, and a pub const where it is imported or qualified. Two modules may each declare a const of the same name.
    • Type aliases: type Meters = float64, generic type Index[V] = HashMap[str, V], pub type exported and imported by name like any other item. An alias is transparent (a Meters is a float64); it is resolved on the token stream before parsing (compiler/alias.sten), so every type position accepts one. A cycle, a wrong number of type arguments, a non-type right side, a name that clashes with a struct or enum, and importing a private alias are compile errors. stenopos doc lists pub aliases.
    • uint64, a 64-bit unsigned integer, with the same rules as the other integer types: checked +/-/* (going below zero is an overflow too), wrapping_add/wrapping_sub/wrapping_mul, casts to and from every other integer type and float64, struct fields, List[uint64] (sorted in unsigned order), map values, consts, and interpolation. Literals adapt to it, and a literal above the int64 maximum (up to 2^64-1) is a uint64. examples/unsigned.sten.

    • Hex and binary integer literals: 0x6a09e667, 0b1010, with optional _ separators (0xffff_ffff).

    • Code-shaping annotations take effect: @inline, @hot, @cold, @no_return, @section("name"), @module_init and @module_exit become LLVM function attributes and sections. A @no_return function may not return, and aborts if it ever reaches its end. @deprecated("msg") warns at each call. @repr("C") checks that every field has a C layout. examples/annotations.sten, examples/no_return.sten.

    • Several @requires/@ensures on one function are all checked (joined with &&).

    Removed¶

    • The compiler's own package path: a stenopos.lock near a source file made every build load the packages it named from ~/.stenopos/cache or vendor/, with no content hash, signature or capability limit, beside tagma's checked registry packages. Gone, with the compiler's stenopos.toml reader: stenopos build takes its profile from --release or --profile, and projects belong to tagma. tagma reads Tagma.toml with std.toml only.

    Fixed¶

    • A loop that called a function returning a string or list through a stack cell (substring, interpolation, split, a ?? on a container, ...) grew the stack on every iteration: the compiler allocated the cell where the call was, and an alloca outside the entry block is a new one each time. A long loop overflowed the stack (a spawned task's 1 MiB within 200,000 iterations). Every such cell now lives in the function's entry block with the variables. It also drops the frame pointer every function with one paid for: fib runs 12% fewer instructions. Example temp_cells_in_loops.

    Performance¶

    • The bench gate enforces its budgets against C for binary size (1.5x), build instructions (2.0x) and run instructions (1.5x): every workload meets them (worst: size 0.99x, build 0.77x, run 1.21x), so missing one now fails CI. Peak memory stays tracked (strings is at 1.52x).
    • String building takes one allocation: a chain of + on strings, and interpolation (which folds to one), sums the parts' lengths, allocates once and copies each part in, where each + allocated, copied the whole prefix again and freed the last one. Empty literal parts are skipped, so "{n}" is just the number's text. Example concat_parts.
    • Integers are formatted without snprintf (two digits per division, one copy). With the single allocation: the bench's strings runs 51% fewer instructions, map 47%, structs 40%.
    • Release binaries call malloc and free directly: the allocation ledger (STENOPOS_MEMLOG) is a debugging aid, now in draft builds (and stenopos run) only. A shipped program no longer prints its heap addresses when the variable is set.
    • An integer overflow check no longer costs every call of a function its prologue. Its failure path called a noreturn function, and LLVM won't shrink-wrap (save registers only on the paths that need them) around a block that ends in unreachable; it now calls stenopos_overflow(), declared cold, which takes no argument (no stack slot for the message) and still never returns. fib's base case runs 4 instructions instead of 10: the bench's fib runs 20% fewer instructions (1.50x C to 1.20x).
    • Release builds put each function in its own section (llc -function-sections -data-sections), so the link's --gc-sections drops what the program never calls, such as the drop and clone helpers emitted for struct types it doesn't copy: the bench's structs binary is 4 KiB smaller (1.28x C's size to 0.99x).

    • Release builds start fewer processes: opt and llc run in one shell with the LLVM version probe, pass bitcode instead of IR text, and clean up in the same shell; the runtime object's freshness check and the host check no longer start a second shell.

    • Builds are faster: the driver's LLVM version check ran llc --version through a second shell and grep, about 40% of the compiler's own share of a small program's build; the shell it already runs now matches the text itself.

    • The bench gate failed in CI on every build (+1.5% build instructions) with no change to the compiler: glibc picks its string and memory routines by CPU, so the CI runner and the machine that recorded the baseline count differently. The gate now pins glibc to its baseline x86-64 routines (GLIBC_TUNABLES), gates compile (the build without the C toolchain it ends in, whose share drifts with the image) and reports build against C only, runs every measured command in a fixed minimal environment (CI's ~100 DRONE_* variables cost ~2.4M instructions per build), and prints the numbers it measured when they don't match the baseline. Baseline re-recorded.
    • The valgrind gate skipped an example that failed to build (and reported PASS): now that is a failure, and the gate finds std the way the bootstrap does, so std-importing examples are checked too.
    • The host built-ins (arg, exec, getenv, read_file, write_file, read_stdin, write_stdout, fail, throw, tcp_*, str_from_byte) check their arguments: a wrong count or type is a compile error naming the signature (argument 1 of \exec(str)` must be a str, not `int32``), where it used to compile into a broken call (L64).
    • Leaks found by running every example, course program and test suite under valgrind (L56–L58): discard f() (and a bare call to an @ignore_discard function) never freed the result: a fresh str, list, map, struct or present nullable is now dropped, a borrowed one left alone. A temporary list of structs passed to a call (describe(tokenize(s))) freed only its storage; its elements are now dropped like a list variable's.
    • More leaks, found by running the compiler and tagma themselves under valgrind (L59–L61): clear() on a list of strings or structs dropped the elements without freeing them; a struct popped off a list (Tok t = xs.pop(), discard xs.pop()) was never freed; the value contains/index_of search for leaked when it was a temporary (xs.contains(a + b)); and a list_new() argument was freed without the strings the callee pushed into it (it now takes the parameter's type).
    • A map a call returns, passed straight to another call (size(tally(s))), crashed the compiler (or produced invalid IR); it is now passed and then dropped like a list temporary.
    • HashMap types with a container value (HashMap[str, List[str]], HashMap[str, HashMap[str, int32]]) can be written as parameter and return types, and maps nest inside lists to any depth (List[HashMap[str, List[int32]]]): signatures read only a one-token map value. One parser function now reads every container type.
    • std-differential no longer exempts json/test_json.sten from the leak gate: it has been leak-free since the throw-unwinding fixes.
    • tagma test: a test in tests/ can import the project's own modules from src/ (a library's tests couldn't import the library). stenopos test and tagma test: a @test function that declares a capability runs (the generated harness's main now declares every capability the file does).
    • tagma registry check judges a git checkout's layout by what git tracks (what is published), so the registry pipeline's scratch files don't count; syntagma.lock and .gitignore belong to the layout.
    • tagma registry check --previous no longer takes index/.keep (which keeps an empty index in git) for a removed package.
    • A call through a function value borrows list and map arguments, as a direct call does; it deep-copied them (so a push through it was lost), and copying a map crashed the compiler.
    • A spinlock spins briefly, then yields its time slice. A waiter used to spin for as long as it took, so with more runnable threads than CPUs (a busy machine, a small container, valgrind) it could hold the CPU the lock's holder needed; threads_spinlock hung under valgrind for hours.
    • !, unary - and ~ on a nullable value are errors until it is checked for null, like every other operator; ! reached llc with invalid IR.
    • ??: its default runs only when the left side is null (a call or other expression used to run every time); fallbacks chain (a ?? b ?? "none" groups to the right); an integer default takes the left side's width (int64? ?? -1 was invalid IR); the default must have the left side's type, and the left side must be able to be null, each with an error that says so (they reached llc, or took a wrong type). A fresh struct on the left is handed over instead of copied, which leaked it.
    • Returning a fresh value from a str?, T? or List? function (return "n{k}") hands it over; it was copied, and the original leaked.
    • A struct passed to spawn is freed when the Hemerodrome finishes; the copy it was given leaked.
    • Diagnostics name struct, List, HashMap, nullable and dyn types; they called every one of them int32.
    • The valgrind gate gives each example a time limit (VALGRIND_TIMEOUT, 600 s by default) and fails on a hang. A lock example livelocked under valgrind's one-thread-at-a-time scheduler once, stalled the gate for hours and was then counted clean.
    • A newline after the * of import a.b.* was taken for a line continuation (* is also multiplication), so a following import line was merged into it and its names were never imported by the alias pass.
    • uint64?, uint32?, bool? and nullable enums: uint64? emitted invalid IR (its type code fell outside every band), bool? lost its bool-ness (e!! was an int32), an integer literal could not be returned as uint32?, and Color? c = ... did not parse as a declaration.
    • a ?? b where a is an owned str? (a call result) leaked the string: the result was a borrowed select, so nothing freed it. The value is now transferred to the result, and the default copied to match (valgrind: return_safe_nav).
    • The benchmark gate failed in CI on numbers recorded on a different machine. The baseline is now recorded in CI's own image (tests/bench/record.sh), a warm-up build fills the runtime cache before measuring, and start-up and peak-memory noise get an absolute slack.
    • Returning a ?. result that is null copied an undefined string (a crash) and, once that was fixed, leaked a buffer: a null is now all zeros, and only a present value's inner is copied. examples/return_safe_nav.sten.
    • Generic functions over generic structs: func swap[A, B](Pair[A, B] p) -> Pair[B, A] infers A and B from the argument and is emitted under its own name (it reached llc as an undefined function).
    • Diagnostics in a program that imports std point at the right file and line (main.sten:3:11, not line 285 of the merged source).
    • A bool returned where a number is due (or the reverse) is a located error; a bool casts to any integer type and float64; a cast from a str or a struct says so; stenopos fmt indents multi-line case bodies.
    • stenopos test builds its harness in a private scratch directory, never next to the source.
    • Methods on a generic struct work (struct Box[T] { .. func get() -> T }): each instance registers its own methods, and their bodies are parsed after the enclosing function (parsing them mid-declaration corrupted it).
    • ?. chains through nullable fields work: a member that is itself nullable is not wrapped again (a?.b?.c ?? d); a chain used to crash the compiler.
    • Struct fields can nest containers (List[List[T]], HashMap[str, List[T]]); the nested type registered a helper struct in the middle of the field list and scrambled both.
    • !! on a value a null check already narrowed is a no-op instead of a parse error; on a value that can never be null it says so.
    • A struct literal passed to a nullable parameter is freed correctly (it reached llc as ill-typed IR).
    • A fixed-size array parameter and a backslash inside { } in a string get messages that say what to write instead.
    • A write to a captured variable inside a lambda is an error. Captures are copies; count += 1 in a closure was accepted and silently lost (the closure kept returning the old value).
    • A capture read in a declaration's initializer read garbage. int32 acc = base inside a lambda gave acc the capture's slot.
    • The single-line extern form works: extern "C" func abs(int32 x) -> int32 was misparsed. A C signature outside the supported types (a str, a pointer, mixed int32/int64) is an error instead of a wrong declaration.
    • join() takes no separator (an argument was silently ignored; use std.string's join(xs, sep)), and interpolating a list, map, struct or closure is an error instead of reaching llc as ill-typed IR.
    • An unclosed { in a string is reported where it is. The rest of the file was lexed as code, which could crash the compiler.
    • Memory safety: a container read is a copy. Song b = s.first() (and last(), and HashMap.get) took the element the container owns without a copy: returning or freeing b left the container holding freed memory (a use after free), and a change to b showed in the list. Only get copied. examples/container_elements.sten (valgrind-clean).
    • Security: no fixed /tmp paths. Module resolution ran a script from a predictable path (/tmp/stenresolve.<n>.sh), so another local user could plant it, and concurrent builds clobbered each other ("cannot find module" at random). The language server mirrored source to a fixed, shared /tmp file. Both use a fresh private (0700) scratch directory now.
    • List methods check the element type. push, set, contains and index_of accepted a value of another type (an int64 into a List[int32]) and produced IR that only llc rejected; an integer literal still adapts.
    • Security: secret arithmetic no longer branches on a secret. A checked +/-/* on a secret[T] value branched on its overflow flag, which is secret: a timing leak. It is now an error; secret arithmetic is modular (wrapping_add, wrapping_sub, wrapping_mul). A secret shift amount is rejected too (the range check branches on it). ADR-0010, amended.
    • Security: the @sensitive wipe survives release builds. The wipe before free was a plain memset, a dead store to memory about to be freed, and opt -O2 deleted it, so release binaries never wiped. It is a volatile memset now, and the bootstrap checks it survives -O2.
    • Calls through dyn take arguments and can be statements. A method with parameters dispatched through dyn skipped its ( ) without reading the arguments, a void call through dyn was not a statement, and dyn Trait could not be a parameter type. Arguments are now parsed and checked against the trait, a concrete value is boxed at the call, and boxing a struct that does not implement the trait is an error (it used to fail in llc). examples/dyn_args.sten.
    • A throw no longer leaks the call's temporaries. A string or struct built for an argument was freed after the call returned, so a callee that threw leaked it. The runtime now holds them while the call runs and frees them when a throw unwinds past it (only in programs that contain a try). examples/throw_temps.sten.
    • Clear CLI and import diagnostics. An unknown command or option is reported as such (it used to be read as a file name, or reach dirname); an import of a module that can't be found names the module and where std was looked for (it used to surface as "unknown function"); import a.b.* says it is not supported yet (it used to report a raw-pointer error).
    • No annotation is silently ignored. The lexer used to drop every annotation it did not know, with its arguments, so a misspelling (@sanitiser) or a documented annotation with no implementation compiled without effect. An unknown annotation is now an error (with a "did you mean" suggestion), and so is one in the wrong place (on a struct, an enum, a statement, a field) or one not built yet (@packed, @aligned, @opaque).
    • Contracts on methods and generic functions are enforced. @requires and @ensures were dropped on generic functions, rejected on struct methods, and lost on inherited methods and trait defaults.
    • Method annotations are checked like function annotations. @cap, @pure, @io, @net, @sink, @tainted and the rest had no effect on methods: the body was unchecked (a method could call read_file with no @cap(File)) and so were its callers. Both are checked now, and a method call carries its security color.
    • An annotation on a generic function no longer leaks onto the next function. The signature pre-pass kept a generic template's pending annotations, so @pure func id[T] made the following function @pure. The call-site annotations on generic functions are rejected until instances carry signature flags.
    • uint32 now has unsigned semantics for values of 2^31 and above. Comparison, /, %, >>, overflow checking, cast[int64], println and indexing all used the signed forms, so 4000000000 > 5 was false and 4000000000 / 2 was
    • They now use the unsigned instructions (ult, udiv, urem, lshr, uadd.with.overflow, zext, %u).
    • A literal adapts to the integer type beside it for every integer type, not only int64: a / 2 and h >> 28 work on a uint32. A real mismatch names both types ("mixed integer types uint64 and int64") instead of always saying int32/int64.
    • wrapping_add/sub/mul require two operands of one integer type (a literal adapts). Mismatched widths produced invalid IR.
    • Negating an unsigned value is an error instead of a silent wrap.
    • A return value adapts to an integer return type, and a different integer width is an error. return 0 - 1 from an int64 function, or returning an int32 from one, emitted a ret of the wrong width that llc rejected. compiler/smoke/compile-fail/return_int_width.sten.
    • A statement the parser doesn't recognise is now an error, not the end of the function. Inside a function body, a token that starts no statement used to end the statement list silently: everything after it was dropped and the function compiled to an empty one that exited 0. It now reports "expected a statement". compiler/smoke/compile-fail/no_statement.sten.
    • The reserved types int8, int16, uint8, uint16, uint64 and float32 are a clean error. They are reserved words but not implemented yet, so a declaration such as uint64 u = 5 hit the case above and silently emptied its function. It now says the type is not implemented yet. compiler/smoke/compile-fail/reserved_type.sten.
    • Shifts are checked. x << n and x >> n with n outside 0..width-1 are undefined in LLVM and produced a different garbage value on each run (for example 1 << 62 on an int32). They now abort with "shift amount out of range", like integer overflow. Shifts by an in-range literal are unchanged and cost nothing extra. examples/shift_range.sten.

    Performance¶

    Each program is written twice, in Stenopos and in C, and both must print the same output. Stenopos builds with stenopos build --release, C with cc -O2 -s.
