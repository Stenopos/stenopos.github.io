    Writing a service¶

    A service is a program that runs until it is told to stop: it answers requests, does work in the background, and finishes cleanly when Kubernetes (or systemd, or Ctrl-C) says so. This page builds one and explains each part. Everything here is in the standard library from rc.7.

    The whole service¶

    An HTTP endpoint that queues jobs, a worker that does them one at a time, health probes, and a clean stop on SIGTERM:

    import std.net.{Conn, Listener, listen, accept, close}
import std.http.{Request, HttpConn, serve, limits, text, json}
import std.os.{notify_signals, exit, SIGTERM, SIGINT}
import std.time.{sleep_ms, rfc3339, unix}

// One connection: requests until the client is done.
@cap(Network)
func handle(Conn c, chan[str] jobs) -> void {
    HttpConn h = serve(c, limits())
    bool open = true
    while (open) {
        Request? got = h.next()
        if (got == null) {
            open = false
        } else {
            Request r = got!!
            if (r.path == "/healthz" || r.path == "/readyz") {
                h.respond(text(200, "ok\n"))
            } else if (r.path == "/jobs" && r.method == "POST") {
                jobs.send(r.body)
                h.respond(json(202, "\{\"queued\": true\}"))
            } else {
                h.respond(text(404, "not found\n"))
            }
        }
    }
    discard close(c)
}

@cap(Network)
func http_server(Listener l, chan[str] jobs) -> void {
    while (true) {
        spawn handle(accept(l), jobs)
    }
}

// The work: one job at a time, a heartbeat when idle.
func worker(chan[str] jobs, chan[str] done) -> void {
    while (true) {
        str? job = jobs.recv_timeout(10000)
        if (job == null) {
            println(rfc3339(unix()) + " idle")
        } else {
            sleep_ms(50)                       // the job's real work goes here
            done.send(job!!)
        }
    }
}

@cap(Network)
@cap(Process)
func main() -> void {
    chan[int32] stop = chan()
    notify_signals([SIGTERM, SIGINT], stop)
    chan[str] jobs = chan()
    chan[str] done = chan()
    spawn http_server(listen(8080), jobs)
    spawn worker(jobs, done)
    println("listening on :8080")
    bool running = true
    while (running) {
        str? finished = done.recv_timeout(1000)
        if (finished != null) {
            println("done: " + finished!!)
        }
        if (stop.try_recv() != null) {
            running = false
        }
    }
    println("stopping")
    exit(0)
}

    tagma run
curl localhost:8080/healthz                  # ok
curl -d 'resize photo 1' localhost:8080/jobs # {"queued": true}
kill -TERM <pid>                             # stopping

    Tasks and channels¶

    Each spawn starts a Hemerodrome, a lightweight task. Thousands are cheap. Tasks share nothing by default: they hand values to each other over channels (chan[T]), and a value sent is moved, so only one task owns it at a time.

    A task that waits (on a socket, a timer, a channel, a child process or a signal) parks: its worker thread runs the other tasks meanwhile. That is why the server, the worker and main above can all wait at once, even on a machine with one CPU.

    Waiting is always bounded when you want it to be:

    Wait Forever With a deadline Without waiting
    A channel c.recv() c.recv_timeout(ms) → T? c.try_recv() → T?
    A socket recv(conn) recv_timeout(conn, ms) → str? poll(conns, 0)
    A connection connect(host, port) connect_timeout(host, port, ms)
    Time sleep_ms(ms)

    null means "nothing arrived in time"; the empty string from a socket means the peer closed it.

    A function can start a task and hand back its channel:

    func start_worker() -> chan[str] {
    chan[str] jobs = chan()
    spawn worker(jobs)
    return jobs                 // the caller owns it; the worker keeps running
}

    Channels, locks, semaphores and atomics are reference counted (from rc.8): the scope that creates one holds a reference, and so does each task it is given to. A function's end lets go of its reference and never waits: the handle lives on while a task still holds it. (In rc.7 such a function waited for every task in the program, so a request handler that made a channel for its own use hung in a service; ADR-0045.) Only the end of main waits for tasks.

    Keep a task to wait for it or stop it (from rc.8):

    task t = spawn worker(jobs)
// ...
t.cancel()                  // stop it: it unwinds at its next wait
bool finished = t.join()    // wait; true if its function returned
bool over = t.done()        // has it ended? (doesn't wait)

    A cancelled task stops at its next waiting point (a channel, a socket, a timer, join): it unwinds like an exception that no catch takes, so its values are freed and its defer and finally blocks run. A task that never waits can't be cancelled.

    HTTP¶

    std.http serves one connection per task. serve(conn, limits()) reads requests (keep-alive included) and answers malformed or oversized ones itself: 400, 431 for headers over 16 KiB, 413 for bodies over 1 MiB, and a client silent for 10 s is dropped. Change limits()'s fields to change those. next() returns null when the client is done.

    The 10 s is per read, not per request: a client that trickles one byte at a time can keep a connection open far longer, and nothing yet caps how many connections are open at once. On the public internet, run the service behind a proxy or load balancer that enforces both. Deadlines for the header block and the body, and a connection cap, are planned.

    A handler that throws ends the whole program (an error nobody catches): catch errors around each request when one bad request shouldn't stop the service.

    The client is a separate module, std.http.client, so a server that never makes requests doesn't link OpenSSL:

    import std.http.client.{ClientRequest, request, get, post_json, fetch}
import std.tls.{pinned}

Response r = get("https://gitea.example.com/api/v1/version")
Response p = post_json("http://localhost:8080/jobs", "\{\"id\": 1\}")
ClientRequest q = request("GET", "https://10.0.0.1/api/self")
q.tls = pinned("5f:3a:...")             // a device with a self-signed certificate
q.headers.push("Cookie: TOKEN=...")
q.timeout_ms = 5000
Response s = fetch(q)

    A failure (refused, timed out, an untrusted certificate) throws, saying why; an HTTP error status is just a Response with that status.

    TLS¶

    std.tls uses the system's OpenSSL, linked into programs that use std.tls or std.http.client, so their image needs libssl3 (it comes with ca-certificates); a program that uses neither doesn't. It speaks TLS 1.2 and 1.3 only. There are two ways to trust a server, and checking nothing is refused:

    • verified(): the certificate chains to a trusted CA (the system's, or ca_file) and names the host.
    • pinned(sha256): exactly this certificate, as openssl x509 -noout -fingerprint -sha256 prints it. For devices with self-signed certificates. A wrong pin fails before anything is sent.

    Stopping¶

    Kubernetes sends SIGTERM, waits (30 s by default), then sends SIGKILL. Deliver signals into a channel and finish what you are doing:

    chan[int32] stop = chan()
notify_signals([SIGTERM, SIGINT], stop)
// ... in the main loop:
if (stop.try_recv() != null) {
    running = false
}

    Then end with exit(0). Returning from main waits for every task, so work a program started is always finished, never cut off. A service's accept loop never finishes, so a service ends with exit(code), which flushes output and stops the tasks: each worker gets up to 1 s to reach a point where it can stop. If a program does return from main and is still waiting after 3 s, it says so on stderr, with the way out.

    exit_grace(ms) sets a limit for that wait: past it, the program says which wait ran out and exits with 124. A batch job leaves it unset, so its work always finishes; a service might set exit_grace(25000), inside Kubernetes's 30 s.

    Files and logs¶

    std.fs does what a shell would, without a shell: read (null when the file is missing), write_atomic (a reader never sees half a file), append, list_dir, stat, mkdir_all, rename, remove_all, temp_dir, chmod, set_umask. std.logging writes leveled records to the console or a file; a file logger appends each record in one write, so tasks logging at once never lose lines.

    For programs, std.os.execute(["tar", "-czf", out, dir]) runs one without a shell and returns its exit code, stdout and stderr: nothing in an argument is ever interpreted.

    Capabilities¶

    Every function that touches the outside world says so: @cap(Network), @cap(File), @cap(Process). main above declares Network and Process; the compiler refuses a function that uses a capability it doesn't declare, so tagma caps lists exactly what a service can do, and a dependency gets only the capabilities its allow grants it.

    Building and running it in a container¶

    tagma build --release                     # target/release/<name>, stripped and hardened

    FROM debian:bookworm-slim
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates \
 && rm -rf /var/lib/apt/lists/*           # libssl3 for std.tls comes with it
COPY target/release/myservice /usr/local/bin/myservice
USER 65534
ENTRYPOINT ["/usr/local/bin/myservice"]

    The binary needs only the C library (and libssl if it uses std.tls or std.http.client). Its output is flushed line by line when it goes to a pipe or a terminal, so kubectl logs shows each line as it is printed. Point Kubernetes's probes at /healthz and /readyz.

    To keep a log of builds, add [output] log = "logs/build.log" to Tagma.toml (where tagma's messages go).
