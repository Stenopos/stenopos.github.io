    rc.7: programs that run as services¶

    v1.0.0-rc.7 is about programs that run until they are told to stop: an HTTP endpoint, a worker, a connection to a device, and a clean exit when Kubernetes sends SIGTERM. Everything a service needs is in the standard library now, written in Stenopos, and none of it needs a shell.

    Tasks that wait¶

    A Hemerodrome (a spawned task) that sleeps, or waits on a socket, a channel, a child process or a signal, now parks: its worker thread runs the other tasks meanwhile. A server, a timer and a client run together on a single thread. Every wait can have a deadline:

    str? job = jobs.recv_timeout(10000)     // null: nothing within 10 s
str? got = recv_timeout(conn, 5000)     // the same for a socket

    Functions can return a channel they created (start a worker, hand back its channel), and spawn takes str arguments.

    HTTP and TLS¶

    std.http is a server and a client. The server runs one task per connection with keep-alive, size limits and a timeout per read; the client (std.http.client) speaks http and https and decodes chunked bodies. Both read framing strictly (RFC 9112): anything two parsers could read differently, which is how requests are smuggled, is refused. CI fuzzes them against Python's parsers and attacks a live server on every build.

    std.tls uses the system's OpenSSL, linked only into programs that use TLS, and speaks TLS 1.2 and 1.3 only. Trust a server through the CAs (verified()), or pin a device's self-signed certificate (pinned("5f:3a:...")), checked before anything is sent. Checking nothing is refused.

    Stopping cleanly¶

    chan[int32] stop = chan()
notify_signals([SIGTERM, SIGINT], stop)
// ... when stop has a signal: finish the work in hand, then
exit(0)

    Returning from main waits for every task, so work a program started is always finished. A program still waiting 3 s after main returned says so; exit_grace(ms) sets a limit. exit() frees what the program holds before it ends: worker threads, OpenSSL's tables, the runtime's own buffers.

    See Writing a service.

    Security fixes¶

    A review of the whole project on 2026-11-14 found four critical problems, all fixed in this release. Two of them are in rc.6: don't run rc.6's tagma check, tagma build or stenopos check on a project you don't trust.

    • Commands from names in a project tree. tagma and stenopos check built shell command lines from paths and package names, so $(...) in a directory or dependency name ran. Every value is now quoted, package names are checked, and the bootstrap builds a hostile tree on every run. rc.8 removes the shell from the toolchain entirely.
    • A use-after-free through !!. !! on a nullable struct handed out the nullable's own storage; it now gives a copy.
    • A server killed from outside. An uncaught error in any task aborted the process, and accept threw when descriptors ran out, so a few hundred idle connections stopped any std.http service. An uncaught error now ends the program cleanly (exit 70, documented), and accept rides out descriptor exhaustion.
    • Request and response splitting. std.http sends no CR, LF or NUL from a program's values in a request or response.

    One more was found by our own fuzzing while the release was being built: std.http trimmed control bytes away before reading a header or a chunk size, so Content-Length: 1 followed by a control byte read as 1, where other HTTP parsers refuse it. Two parsers that disagree about where a message ends is how requests are smuggled past a proxy. A start line or header with any control byte but tab is now refused, and chunk sizes are read strictly.

    Also from the review: TLS setup steps fail closed and a closed connection's handle can't reach a newer one; every allocation in the runtime is checked (stenopos: out of memory instead of a crash later); exit() no longer cleans up OpenSSL under a task still using it; and output is flushed line by line when it goes to a pipe, so kubectl logs shows each line as it is printed.

    Performance¶

    Every program used to start twice: it raised its stack limit to 1 GiB and executed itself again, which made a hello-world take 1.7 times as long as C's (3.1 ms against 1.8 ms). Programs now run on the system's stack, as C programs do; one that needs more says so ([build] stack = "256MiB" in Tagma.toml), and a stack overflow says so instead of a bare segmentation fault.

    Every allocation is now checked, and allocating got cheaper anyway: the check costs one test, the runtime calls libc without PLT stubs, and integers become strings without a copy. Measured by CI against rc.6, the map benchmark runs 2.0% fewer instructions and strings 2.5%.

    One number went the wrong way: the map binary grew from 14 KB to 18 KB. Binaries grow a page (4 KB) at a time, and this release's runtime additions put map's code just past a page boundary, by about 340 bytes. rc.8 brings it back under, as the first step of the size work in the plan. The compiler's own work grew 1.1%.

    Each program is written twice, in Stenopos and in C, and both must print the same output. Stenopos builds with stenopos build --release, C with cc -O2 -s.     Known limits¶

    What this release does not do yet, each with its plan:

    • A function that creates a channel, lock or atomic and doesn't return it waits for every task in the program when it returns. In a service, create them in main. rc.8 makes them reference counted.
    • Using a value after send moved it isn't refused at compile time.
    • std.http's timeout is per read, and connections aren't capped: put a public service behind a proxy.
    • Taint tracking covers the functions you mark; the standard library's sources and sinks are marked by 1.0.

    Files, programs and time¶

    std.fs (read, write_atomic, append, list_dir, stat, ...), std.os.execute(["tar", "-czf", out, dir]) (no shell: an argument is never interpreted), std.time (clocks, sleeping, UTC and local formatting), and std.net by name, IPv4 or IPv6, with failures that say why: connect mosquitto:1883: connection refused.

    tagma¶

    • Progress lines go to stderr, so tagma run > out.txt holds only the program's output. [output] in Tagma.toml sends them to stdout or nowhere, and log = "logs/build.log" keeps a log of every run, the compiler's diagnostics included.
    • tagma doc --prepare gives every file, type and function a /// doc block (existing comments become docs; the rest get stubs), and tagma doc --check fails while a public item is undocumented. Every public item in the standard library is documented.

    Fixed¶

    • A program's functions were taken as part of the last module it imported (duplicate function 'rfc3339' in module 'std.time').
    • A module imported both directly and by another import could be placed after its user ("unknown type Conn").
    • read_file read /proc and /sys files as empty.
    • std.logging's file logger and std.io.append_file rewrote the whole file for every line; they append in one write now.
    • Escapes: \xNN and \u{...} exist, and an unknown escape is an error.

    The full list is in the CHANGELOG.
