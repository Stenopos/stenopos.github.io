    What's new in v1.0.0-rc.5

    Added¶

    • tagma, the build tool (ADR-0038). Syntagma now ships two commands: tagma for projects and stenopos, the compiler, for single files. tagma new, build, run, check, test, fmt, lint, doc and clean work on a directory with a Tagma.toml ([package] name, version and edition, plus local path [dependencies]). tagma calls the compiler's modules in-process and shares its version. The easter-egg commands moved from stenopos to tagma. See docs/TAGMA.md.
    • Editions. edition = "2026" in Tagma.toml names the language edition; the compiler refuses editions it does not know.
    • Release bundles. Each release ships syntagma-<version>-linux-<arch>.tar.gz (bin/tagma, bin/stenopos, lib/stenopos/ with the runtime and std) for all six architectures, plus standalone tagma-linux-<arch> binaries. The installer installs the bundle.
    • std.lock pins the std commit a release bundles and CI dogfoods, instead of choosing std by date.

    Changed¶

    • selfhost/ is now compiler/, and its modules are compiler.*.
    • The compiler finds its runtime and std beside its own binary (<prefix>/lib/stenopos/), so an install anywhere works without STENOPOS_HOME.
    • Inside a project, stenopos new and stenopos build/run/test without a file point to tagma.

    • The installer moved to public/install.sh (the one served from GitHub).

    • Generic structs as function return and parameter types. func make() -> Box[int32] and func f(Box[int32] b) now work (both were a clean error / silent int32). Generic struct templates are pre-registered before the signature pre-pass, so the concrete instance resolves in both collect_signatures and the body parse (parse_func/ parse_method); return Box { .. } resolves the generic literal against the declared return type. Forward references, methods, and multi-arg generics (Pair[int32, str]) all work, valgrind-clean. examples/generic_return.sten.

    • Conditional compilation: @cfg(...). A parse-time gate on top-level declarations, selected by build config — @cfg(target_arch == "x86_64"), @cfg(ptr_width == "64"), @cfg(profile == "release"), @cfg(feature == "debug"), with &&/||/! and ==/!=. Unlike a const-gated if (stripped only by the release optimizer, and still type-checked), @cfg is evaluated in the parser in BOTH passes, so an excluded declaration is never parsed, type-checked, or registered — enabling genuinely platform-specific code (e.g. x86_64-only inline asm invalid on aarch64), and two same-named @cfg variants coexist with no duplicate-definition error. Config comes from --target (arch/os/endian/ptr_width), --release (profile), and the new repeatable --feature NAME / --define NAME. examples/cfg_select.sten.
    • Top-level const globals. const int32 W = 10 (and int64/uint32/ float64/bool/str) at file scope declares a named, immutable, compile-time literal constant visible to every function in the file. It is substituted in place at each use — no storage, no indirection — so a global const name is never an assignable slot. Initializers must be a literal of the declared type; a computed expression or a type mismatch is a clean error. A local may shadow a global const. examples/const_globals.sten.

    Fixed¶

    • Block-local variables are now correctly scoped. A name declared inside a block ({ } of an if/while/for/do/try/with/match/unsafe) was leaking out — a nested int32 x = 2 overwrote an outer x, and the inner binding stayed visible after the block. Now a nested declaration is local to its block: shadowing is restored on block exit, sibling blocks reuse names freely, and using a block-local after its block is undefined variable. Implemented WITHOUT popping names (a block-horizon stack + a sparse dead-set), so slots stay monotonic and the const/color/codegen paths are unchanged. examples/scoping.sten. (Follow-up: reject same-scope redeclaration.)
    • Passing a fixed array directly to a slice parameter is now a clean error. f(a) where a: int32[3] and f takes int32[] used to be accepted but read garbage (.len() returned 1) and segfaulted on iteration — a fixed array is not a {len,ptr} slice view. Slice it first: f(a[0..<3]). examples/compile-fail/array_as_slice.sten.
    • Returning a generic struct type is now a clean error, not a silent mis-compile. func make() -> Box[int32] previously either failed with a confusing parse error or (as a forward reference) silently recorded int32 and returned garbage, because the signature pre-pass runs before generic structs are registered. It now reports that the case isn't supported yet (return a concrete struct or the inner value). Full support is a generics follow-up. examples/compile-fail/generic_return_type.sten.
    • do { ... } while (cond) is now implemented. It previously parsed but emitted NOTHING — the body and everything after it in the function silently vanished. It now compiles to a proper bottom-checked loop (the body runs at least once, the condition is tested at the bottom; break/continue work), and a do not followed by while (cond) is a clean parse error. examples/do_while.sten.
    • Reassigning a nullable struct/str field no longer emits ill-typed IR. t.left = insert(t.left, v) where left: Tree? stored a raw pointer into the {i1, ptr} nullable slot (rejected by llc), which blocked linked lists and trees built by field mutation. The assignment now widens a bare T -> T? (and drops the replaced inner, null-safe), so building and overwriting are both valgrind-clean. examples/bst_mutate.sten.
    • A local const declaration no longer silently drops its initializer. const int32 x = 42 previously parsed but left x empty (the const modifier was never consumed, so the declaration mis-parsed); const is now a recognized declaration modifier and the value is kept.
    • const immutability is now enforced. Reassigning a const — local (const int32 x = 1 then x = 2) or global (W = 5 on a top-level const, which used to crash with an out-of-bounds write) — is a clean compile error. Covers = and the compound forms. examples/compile-fail/const_reassign.sten.
    • A struct literal naming an unknown field is now rejected. Point { x: 1, zz: 9 } where zz is not a field previously mapped the stray value to field 0 (silently overwriting x); it now reports "struct 'Point' has no field 'zz'" (the field-index lookup returned 0 on a miss). examples/compile-fail/struct_lit_unknown_field.sten.
    • Calling an rwlock-only method on a mutex/spinlock (or vice versa) is now a clean error. m.read_lock() on a mutex[T] previously type-checked and emitted a nonsensical call; the parser now validates each lock method against its lock kind (lock/unlock for mutex/spinlock, read_lock/write_lock for rwlock, acquire/release for semaphore) and reports e.g. "mutex has no method read_lock". examples/compile-fail/lock_bad_method.sten.
    • sort() on a List whose element has no natural order is now a clean error. .sort() on a List[struct] (or a float/bool/enum list) previously fell through to the 4-byte sort_i32 path and read each element at the wrong width — a silent mis-compile. It now reports "sort needs an int32, int64, or str element type". examples/compile-fail/list_sort_struct.sten.

    Release key¶

    All releases are signed with the Stenopos Release Signing key. Its primary key is kept offline and only certifies subkeys; CI signs with a dedicated subkey.

    21CB C7C3 F66D FAFD D038  5515 E5FB D284 8395 1BCB

    The key is published on keys.openpgp.org and in the Syntagma repository, and the installer has it built in.
