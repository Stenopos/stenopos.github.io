    What's new in v1.0.0-rc.7

    Security¶

    Found by the review of 2026-11-14 (design/REVIEW-2026-11-14.md). The first two are in rc.6: don't run rc.6's tagma check, tagma build or stenopos check on a project tree you don't trust.

    • Commands from names in a project tree (RV-C1, in rc.6): tagma check/build and stenopos check built shell command lines from paths and names, so $(...) in a path dependency, the package name or a directory name ran. Every value is now quoted as one shell word (one helper, sh_quote), the package name is checked on every command (letters, digits, -, _), and the bootstrap builds a hostile tree and fails if anything runs. (rc.8 drops the shell from the toolchain altogether.)
    • Use-after-free through !! (RV-C2, in rc.6): Node x = n!! on a nullable struct handed out the nullable's own box, so reassigning n freed what x pointed to, and two n!! bindings were one value. !! now gives a copy (or takes over an owned temporary), as ?? and narrowing do (example nonnull_assert_copies).
    • A server killed by its own error handling (RV-C3): an uncaught throw in any task called abort(), and accept threw when the process ran out of descriptors, so a few hundred idle connections stopped any std.http service. An uncaught throw now ends the program cleanly (exit 70, the message, output flushed, workers retired, no core dump; documented), and accept waits through descriptor or memory exhaustion (warning at most every 10 s) and skips clients that gave up.
    • Request and response splitting (RV-C4): std.http sent CR and LF from the program as they were. fetch now refuses a method that isn't a token, a URL with a space or control character, and a header with a CR, LF or NUL; respond sends a 500 instead of a header like that (and says why on stderr), so a value taken from the request can't add headers.
    • Headers read differently from other parsers (found by httpfuzz): std.http trimmed control bytes away, so it read Content-Length: 1 followed by a control byte as 1, and a chunk-size line 0, CR, control byte as 0, where Python's http.client refuses both. A parser that accepts what a stricter one refuses is a smuggling risk. Requests and responses with any control byte but tab in the start line or headers are now refused, and chunk-size lines are parsed strictly (hex digits, then only spaces or tabs before a ; extension).
    • TLS setup fails closed, and handles can't be reused (RV-H4): a failed SSL_set1_host, minimum-version, SSL_set_fd or SNI step now stops the connection instead of continuing with less checking; std.tls speaks TLS 1.2 and 1.3 only (ADR-0046); and each handle carries a generation, so closing or using a stale TlsConn fails instead of reaching the connection that reused its slot.
    • Unchecked allocations (RV-H6): the runtime checked 3 of its 85 allocations. Every one now goes through kxmalloc/kxcalloc/ kxrealloc/kxstrdup, which stop the program with stenopos: out of memory; scripts/ci-runtime-lint.sh (CI) fails on a bare allocation. The scheduler's setup (epoll, eventfd, worker threads) stops with the reason when it fails instead of leaving tasks that never run.
    • exit() gives busy workers 1 s; it no longer runs OpenSSL's cleanup when one of them didn't stop and could still be inside TLS (RV-M5). tagma's log tee waits at most 1 s for its thread at exit, so a daemon started by a build step that keeps stderr open can't hang tagma (RV-M4).

    Costs and follow-ups of these fixes: the clean exit on an uncaught throw adds 183 bytes of code; the map benchmark sat 71 bytes under a page boundary, so its release binary is one page (4 KB) larger and the baseline is re-recorded (the other workloads are unchanged, because each subsystem now registers its exit work when first used instead of being named by the exit path). The audit probe mem-spawn-moves moved from MISCOMPILE to ACCEPTED when spawn learned str arguments: still ADR-0040's missing use-after-move check. A function execute_with uses was called without a declaration (an error for newer C compilers): declared.

    Fixed¶

    • std.http reads framing strictly (RFC 9112), refusing what two parsers could read differently (the way requests are smuggled): a bare CR or LF or a NUL in the headers, folded header lines, header names that aren't tokens, a malformed or conflicting Content-Length, Transfer-Encoding with Content-Length, a transfer coding other than chunked (501), request lines and status lines that aren't HTTP/1.0 or 1.1, a status that isn't three digits, chunk data longer than its size. A 1xx, 204 or 304 response has no body whatever its headers say. Found by httpfuzz.
    • Memory left at exit: exit() now retires the worker threads first (their resolver, OpenSSL and loader state were left behind), stops the signal forwarder, and frees the main thread's try/catch buffers, as a normal return now does too. Every new program is clean under valgrind with all leak kinds shown.
    • A program's own functions were taken as part of the last module it imported, so one named like a function of that module (rfc3339 beside import std.time) was "duplicate function 'rfc3339' in module 'std.time'" (example names_like_std).
    • Imported modules were ordered breadth-first: when the program imported both std.http and std.net, std.http came before std.net, so its use of Conn was "unknown type". Files are now placed after everything they import.
    • read_file read files by their reported size, so /proc and /sys files (size 0) read as "" (example read_proc_file).

    Changed¶

    • Programs start once, on the system's stack. Every program raised its stack limit to 1 GiB and executed itself again before main, so a hello-world took 1.7 times as long as C's (3.1 ms against 1.8 ms; the benchmark ran under valgrind, where that step is skipped, and never saw it). A program now gets the system's stack (usually 8 MiB) unless it asks for more: [build] stack = "256MiB" in Tagma.toml, or --stack <size> on stenopos build and --multi. The compiler and tagma ask for 1 GiB. Running out of stack on the main thread says stack overflow and how to get more, after flushing output, instead of a bare segmentation fault. Programs the toolchain starts (tagma run, tagma test, stenopos run) get the stack limit the toolchain started with, not its 1 GiB.
    • Allocation: stenopos_alloc is malloc, one test and a return (the zero-size and out-of-memory cases on a cold path); the runtime calls libc through the GOT (-fno-plt), not PLT stubs; integers become strings without a copy; map keys are copied inline again. With every allocation checked (RV-H6), the benchmarks run fewer instructions than before (map -2.3%, strings -2.8%, structs -0.9%), no binary grew, and the IR the compiler emits is unchanged. (A NULL test inlined into the program's IR was tried first: it ran faster but cost opt and llc 12% more work on struct-heavy programs.)
    • tests/bench/run.sh --record keeps, for each number, the lower of the baseline and the new measurement: the baseline is a ceiling, tightened by improvements and never loosened by a regression.
    • The compiler and tagma linked OpenSSL: the driver's search for a TLS call found its own search text, a string constant in them. Found by the benchmark gate (3M more instructions per build); the bootstrap now checks which binaries link OpenSSL.
    • Breaking: the HTTP client moved to std.http.client (ClientRequest, request, get, post, post_json, fetch); std.http keeps the messages, the server, parse_url and parse_response. A server that never makes requests no longer links OpenSSL.
    • OpenSSL is linked, not loaded with dlopen (ADR-0046): the compiler adds libssl.so.3 and libcrypto.so.3 to programs that use TLS, and no program links libdl. A missing libssl is now reported by the loader at start, not on the first connection, and a program that uses TLS leaves nothing behind at exit under valgrind.
    • Standard output is flushed line by line when it goes to a pipe or a socket (ADR-0044 D12), so a service's output reaches kubectl logs, journald or | grep as each line is printed. A terminal was already line-buffered; a file or /dev/null stays fully buffered.
    • str.index_of skips to candidates with memchr instead of comparing at every position (the compiler searches its whole output once per build).
    • Breaking: std.http is now a server and client (below). Its old response(status, body) -> str is response(status, content_type, body) -> Response, and text(status, body) replaces it for plain text; parse_request(raw) stays, returning the fuller Request.
    • tagma's status lines (Compiling, Finished, Running, Added, Updated, Fetched...) go to stderr, so tagma run > out.txt holds only the program's output. tagma resolve's answer stays on stdout. Found by the new end-to-end test.

    Added¶

    • tagma doc --prepare and --check. Prepare gives every file, type, function and method a /// doc block: a plain // comment block directly above an item (or a file's header above module) becomes its doc, and an item with none gets a /// TODO: stub. Check fails while a public item (or the file) has no doc or only a stub. std went through it: every public item in std is documented, 1,100 lines of comments became docs.
    • The doc generator: a /// block above annotations (@cap(File)) is the function's (annotations used to cut it off, so every function with a capability lost its docs); a /// block above module describes the module; a blank line ends a doc block; doc lines keep their indentation and line breaks (Markdown paragraphs, lists and code).
    • std.http accepts chunked request bodies (decoded as they arrive, within the body limit; trailers read and dropped).
    • scripts/httpfuzz.py (CI's fuzz step): std.http against Python's http.client and http.server, and a live std.http server under mutated and junk requests, sent whole or in pieces.
    • spawn takes str arguments: the task gets its own copy (a temporary moves in, a variable is copied), freed when it returns (example spawn_str_args).
    • Functions can return a channel (or lock, or atomic) they created, and the caller owns it: func start() -> chan[int32] can spawn a worker and hand back its channel; the worker keeps running. chan[int32] c = start() declares one. Returning a channel a function didn't create is refused (example chan_return).
    • std.os.exit_grace(ms): how long a program may wait for its tasks after main returns; past it, the program says so and exits with 124, cleaning up as exit() does. Unset, main's return waits as long as the tasks take. Either way, after 3 s it says what it is waiting for and how to stop.
    • tagma's [output] in Tagma.toml: status = "stderr" | "stdout" | "none" for its progress lines, and log = "<file>" to append each run (the command line, then everything on stderr: tagma's messages, the compiler's diagnostics, a failing llc or cc). --status, -q/--quiet and --log override it for one run. Errors always reach stderr.
    • std.fs.append(path, text): one O_APPEND write. std.io.append_file and std.logging's file logger use it: they used to read and rewrite the whole file for every line (slow as a log grows, and two tasks logging at once could lose lines).
    • std.tls: TLS client connections (k8s-todo item 6), using the system's OpenSSL (3.x or 1.1), loaded with dlopen the first time a program connects, so programs that don't use TLS don't depend on it. verified() checks the chain (system CAs or ca_file) and the host name; pinned(sha256) trusts exactly one certificate, checked after the handshake and before any byte is sent; asking to check nothing throws. TLS 1.2+, SNI; the handshake and reads wait on the poller, so a task doing TLS lets the others run. Failures throw with the reason (certificate not trusted: self-signed certificate, the certificate doesn't match the pin (it is sha256 ...)).
    • std.http: an HTTP/1.1 server and client (k8s-todo item 7). Server: serve(conn, limits()) and next() -> Request? / respond(Response), one Hemerodrome per connection, keep-alive and pipelining, limits on headers (431) and bodies (413), a slow-client deadline, 400 for malformed requests. Client: get, post, post_json, fetch with headers, a deadline and TLS options; Content-Length, chunked and read-to-close bodies. A Kubernetes probe and curl -d @body.json work against it (tests/e2e/service).
    • Signals on a channel: std.os.notify_signals([SIGTERM], ch) forwards watched signals into a chan[int32] the program owns (from a runtime thread, so no task waits forever; forwarding stops when the channel is freed). std.os.exit(code) ends the program now, after flushing output, even while tasks are waiting: it retires the worker threads first, so nothing they hold is left behind (example signals_on_a_channel).
    • The soak test (tests/soak/run.sh): an MQTT reader on a real broker, a publisher, a timer and an HTTP health endpoint for 24 hours, checking the work done, flat memory and a clean SIGTERM.
    • End-to-end tests (tests/e2e/): install follows the docs in a clean container, from the signed installer through a project with a path dependency, a registry package and every tagma command; service builds a small service on std.fs, net, os, time and channels with a given tagma.
    • Channels: c.try_recv() takes an element if one is waiting, and c.recv_timeout(ms) waits at most ms milliseconds; both give T?, null when nothing arrived, for every element type. A Hemerodrome waiting with a deadline parks on the channel and its worker's timers at once, so the others on that worker keep running (example channels_that_wait; stress chan_timeout_stress races sends against deadlines, natively and under Helgrind).
    • Hemerodromes that wait no longer hold their worker thread (GREEN-THREADS phase 3, ADR-0043 §3.5). Each worker has an epoll poller and a timer heap; sleep, socket reads, writes, accepts and connects, recv_timeout, poll, wait_signal and execute's pipes park the waiting Hemerodrome there, and the worker runs the others. A server waiting on a socket, a ticker and a client now run together on one worker, where the server's wait used to hold the only worker and deadlock them (example tasks_that_wait); 2000 sleeping Hemerodromes take one sleep's time. STENOPOS_WORKERS=N fixes the worker count.
    • Running programs without a shell (ADR-0043 §3.6; std 76b1bcc): std.os.execute(["tar", "-czf", out, dir]) and execute_with(argv, ExecOptions { env, dir, stdin }) return Output { code, stdout, stderr }. Nothing in an argument is split, expanded or interpreted; stdout and stderr are read together (neither pipe can fill and stall the child); the child's environment is empty unless given (environ() lists ours); it starts with default signal handling. A program that can't start throws; a non-zero exit is its code. exec(str) stays the shell path.
    • Signals: std.os.watch_signals([SIGTERM, SIGINT]) and wait_signal(ms) -> int32?, so a service finishes its work before exiting on SIGTERM.
    • Host built-ins os_exec, os_environ, os_error, sig_watch and sig_wait (@cap(Process)), as table entries.
    • std.fs (ADR-0043 §3.7, PLAN MS1; std 2e87f1f): read (null when the file is missing, "" when it is empty), write_atomic (a temporary file, fsync, rename, fsync the directory: never a half-written file), list_dir (sorted), stat (size, mtime, mode, kind; links not followed), exists, mkdir_all, rename, remove, remove_all, chmod, temp_dir (mode 0700) and set_umask, all @cap(File); failures throw read /x: permission denied.
    • Octal literals: 0o755, 0o600 (file modes).
    • std.convert.parse_int64 and parse_int32: null for anything but an optional sign and digits, or a value out of range. parse_int and str_to_int are deprecated (ADR-0043 §3.8).
    • Host built-ins are declared in one table (host_builtin in the parser: runtime function, parameters, result, capability, effect), read by every check and by code generation: a new one is a table line and its C function. The twelve fs_* built-ins are the first.
    • std.net by name, IPv4 or IPv6, with deadlines (ADR-0043 §3.4, PLAN MS1; std 0f63911): connect resolves names (getaddrinfo, each address in turn), connect_timeout(host, port, ms), listen on IPv6 and IPv4, listen_on(addr, port), recv_timeout(conn, ms) -> str? (null: nothing in time), poll(conns, ms) and resolve(host). New built-ins net_resolve, net_error, net_set_timeout, tcp_wait, tcp_poll and tcp_listen_on, all @cap(Network).
    • std.time (ADR-0043 §3.3, PLAN MS1): unix(), unix_ms(), mono_ns(), sleep_ms(), the calendar in UTC or the local zone (utc, local, from_utc, DateTime), and format, format_utc, format_local, rfc3339, rfc3339_local. Times are int64 seconds, exact far past 2038; the calendar is computed in Stenopos (std 038d2cf). Built on four new built-ins, clock_unix_ns(), clock_mono_ns(), sleep_ns(int64) and local_offset(int64): no capability (reading the clock is not an effect on the world), but not @pure. Built-in arguments may now be int64, and an integer literal widens to it. Example time_calendar. Sleeping inside a task still blocks its worker thread until the I/O poller lands (GREEN-THREADS phase 3).
    • String escapes \xNN (any byte, two hex digits) and \u{H} (any Unicode character, 1-6 hex digits, as UTF-8), in strings and, when the result is one byte, in character literals (L69). Example string_escapes.
    • @cap takes a list: @cap(File, Process) and @cap(File | Process) mean the same as one @cap per line (L67, found porting Tux). An unknown name or a malformed list is an error. Example cap_lists.

    Changed¶

    • std.net failures throw, naming the operation, its target and the system's reason: connect mosquitto:1883: connection refused, resolve nas.lan: name not found, connect 10.0.0.9:443: timed out after 5000 ms (audit L70). They returned a handle with fd < 0 and no reason, so a check of fd < 0 no longer fires: catch the exception instead. recv still returns "" at the end of a stream.
    • An unknown escape is an error, listing the valid ones. It used to keep the byte after the backslash silently: "\d" was "d", "\b" was "b", and "\u{80}" became u plus an interpolation (L69).

    Fixed¶

    • A temporary string passed to split or replace (s.split(str_from_byte(0))) leaked. Example temp_method_args.
    • Testing a call's nullable result for null inline (show(find(k) == null)) produced invalid IR (the bool was taken for the call's owned string) and leaked the string. The result is dropped after the test. Example null_test_of_call.
    • Writing to a connection the peer had closed raised SIGPIPE, which ended the program: a service died the first time a client or broker went away. It is now an error (send: broken pipe). Socket calls interrupted by a signal are retried, and sockets are closed in child processes.
    • A string with no closing quote crashed the compiler ("array index out of bounds", no location): a string may span lines, but the lexer didn't count the lines inside one, so every later line number was wrong and the parser ran off the end. Lines inside strings are counted, and a string still open at the end of the file is reported where it starts (L65).
    • An unclosed ( or [ is reported on the line where it opened. It used to surface lines later as "unexpected token after statement", because everything after it was read as one expression (L65). Lexical errors are syntax errors (E0200).
    • A top-level function named like a built-in (fail, println, exec, list_new, ...) is refused, naming the built-in. Calls to it went to the built-in: fail, println and list_new silently never called the user's function, and the others were checked against the built-in's parameters (L66). Methods may still use these names.

    Release key¶

    All releases are signed with the Stenopos Release Signing key. Its primary key is kept offline and only certifies subkeys; CI signs with a dedicated subkey.

    21CB C7C3 F66D FAFD D038  5515 E5FB D284 8395 1BCB

    The key is published on keys.openpgp.org and in the Syntagma repository, and the installer has it built in.
